# Query language

The search bar compiles to ClickHouse filters on the server. The UI never sends SQL.

## Examples

```
level:error
service:api timeout
level:error service:api timeout
level:error OR level:fatal service:api
(level:error OR level:fatal) service:api
status:5*
status:>=500
"connection reset"
path:"/v1/items"
host:api-1
user_id:42
duration_ms:84
duration_ms:>100
duration_ms:>100 duration_ms:<500
http.status_code:500
```

## Rules

- `level:value`, `service:value`, and `host:value` are equality on those columns.
- Any other `key:value` whose key is `[a-zA-Z_][a-zA-Z0-9_.]*` (and not `ts` / `message` / `tenant_id`) is equality on `attr_map[key]`. `path`, `status`, and `user_id` are ordinary map keys. Repeating a key **bare** ANDs the values (`level:error level:fatal` matches nothing). Facet clicks **toggle** membership in that field’s set and rewrite a parenthesised OR group (`(level:error OR level:fatal) service:api`); `only` collapses to one value; a typed group of that shape re-checks the boxes. Detail-panel `+` adds the value to the set (does not replace).
- Comparisons (`duration_ms:>100`, `status:>=500`) are `>` `>=` `<` `<=` on **attr** keys only. The number is a finite decimal (`100`, `0.5`, `-1`). Equality stays a string (`duration_ms:84`). Quotes escape the operator (`duration_ms:">100"`). `duration_ms:>100 duration_ms:<500` is a range. Core fields cannot compare (`level:>error` is a fault). A comparison is true only when the attr parses as a finite number and the operator holds; `not` / `-` is boolean NOT of that predicate (missing and non-numeric values match the negation). Histogram / count / facets for that `q` scan `logs` — the values rollup is equality/prefix, the numeric MV is p99/avg, not a range index. Overlaying `agg=p99:duration_ms` on a comparison query computes p99 of matching rows (budgeted logs scan).
- Bare words are case-insensitive **tokens** of `message` (`splitByNonAlpha` after `lowerUTF8`). `timeout` matches that word (`connection timeout`), not `timeouts`. `"connection reset"` is consecutive tokens (`hasToken` per word plus `hasSubstr` on `splitByNonAlpha`; ClickHouse `26.3` has no `hasPhrase`). `path:"/v1/items"` quotes a value that needs it. `"or"` / `"and"` / `"not"` search those words. A punctuation-only needle matches nothing.
- Space separates tokens and ANDs them. `and` / `or` / `not` are case-insensitive operators. AND (written or juxtaposed) binds tighter than OR. `-` is the same as `not`. Parentheses group. No regex, infix globs, `100..500`, `1e3`, Lucene, or SQL in the URL.
- Prefix globs only: `status:5*` is `startsWith` on that field. `*foo` and `5*0` are faults. A trailing `*` on a bare word is also a fault.
- Invalid idents (`foo-bar:x`) stay message text. Empty values (`level:`), unmatched `(`/`)`, unterminated quotes, and dangling `and`/`or`/`not` are compile errors (400 `{ error, faults }`). The bar shows them after Enter; typing clears the chrome. Live polls skip a broken `q` and keep the last-good results.
- Time range is `range=15m|1h|4h|24h|7d` (or any `\d+(ms|s|m|h|d|w)` up to 365 days, `1ms` ≠ `1m`, `1w` = 7d, `30d` and `2w` parse) or custom From/To. `range` overrides `from`/`to`. Custom spans clamp to 365d. Live keeps sending the same `range` so the window ends now. Custom + Live slides the From/To duration on the client. Live polls add `since=` (newest event) so only new rows and the current histogram bucket come back; the client merges and fills empty buckets so the chart scrolls. A full search still runs every 30s so the sliding window is honest. Mergeable extra timeseries (rollup-backed volume / rate / min / max / sum, unlabeled metric bars) refresh on the 2s `since=` poll like the pinned plot. Whole-window aggregates (Top-N except a complete level projection, window p99/avg, logs-scan extras, labeled metric scans) stay on that 30s pass; while Live is on, widget chrome shows a muted last-updated age only on cards that missed the last 2s poll. Count and rate stats are projections of the merged primary histogram. Only the active Search tab polls (Follow if Live is on; Surroundings and boards do not). Histogram bar width is auto: the finest of `1ms|10ms|100ms|1s|10s|1m|5m|15m|1h|4h|1d|7d` with at most 200 bars (15m → `10s`, 1h → `1m`, 4h → 5m, 24h → 15m, 7d → 1h, 30d → `4h`, 365d → `7d`). `step=` pins a tick; ticks that would exceed 500 bars are disabled; 1 bar is legal at the 1ms floor or as one column of the window’s own grain. Event pages (`ORDER BY ts DESC LIMIT 100`) start in a 1-minute lookback from `to`/`cursor` and widen (4m, 16m, 1h, 4h, 24h, 7d, 30d, 90d, 365d) until they fill or hit `from`, so a dense window does not sort the whole table. The floor / last lookback uses the read budget and refuses (`scan.events`) rather than 500. Load-more (`cursor=` without `since=`) returns events only — histogram and `total` stay from the first search. `events=0` skips the event page and lookback (logs-off widgets). The first search’s histogram still covers the full window. An empty full-window search also returns `ingested` (any row in `logs`, not this window) so the UI can say “No events in this range” instead of “No events ingested yet.” A refused logs scan uses the refuse reason instead of that empty copy.
- The operator UI serializes search to the page URL: `q`, `range` (`15m|1h|4h|24h|7d` or any `\d+(ms|s|m|h|d|w)` ≤ 365d such as `90m`, `30d`, `2w`, or `1w`; `range=custom` with `from`/`to` ISO), `live=1`, `saved=<id>`, `view=alerts` or `view=fields`, histogram `split` / `chart` / `scale=log` / `step=` (bar width; omit for auto), `agg=` / `y=agg` (log-derived overlay or replace-Y), `metric=` / `ml=` (ingested metric overlay, optional label matchers), `logs=0`, compact widget grid `w=` (omit for the default single histogram; `a` is the pinned volume plot and is restored if a copy-link omitted it), and `af=` (pinned attr facet keys, omit when empty). A board copy-link is the same Search URL plus that board’s slot keys as bind params (`saved=s7&install_name=acme-eu&range=4h`); those keys are parsed only against that saved row’s `board.keys`. Copy-link uses `history.replaceState`. Roles and links live in SQLite (`GET/PUT /api/fields`), not in the URL. `GET ?wave=keys|values|suggest` returns that catalog slice; `PUT` returns `{ roles, links }` only. Graph on a linked detail field sets `metric=` + `ml=` from the saved link (mapped label + this value) and does not write that token into `q`.
- Histogram uses `logs_by_minute` when the bar is ≥1m and the query has no message terms and no attr filters (host filters, split-by-host, and core-field `OR` / `NOT` / `-` are included). Interval `< 1m` scans matching `logs` with the read budget (refuse rather than a partial chart). A `1m+` logs-shaped volume histogram uses that same budget. A single attr equality or prefix glob (`status:5*`, or `status:500 OR status:502`) uses `logs_attr_values_by_minute` when the bar is ≥1m. UUID-like / lookup-role / ignore-role equality scans `logs` (bloom on `trace_id` and `mapValues(attr_map)`) so histogram `total` matches the table. Two or more attr keys, an attr under `NOT`, `level:error OR status:500`, a comparison (`duration_ms:>100`), or a message term still read `logs` (message terms use the text index on `message`, not `logs_by_minute`). Values longer than 64 characters, JSON blobs, and UUID-like ids are not rolled up. **Follow this value** on a lookup or id-shaped Fields row opens a new Follow workspace with that `key:value`, pins custom ±5m, and drops `service`/`host`. Buckets carry a `series` map (and `by_level` when the split is level). Search `total` is the sum of those buckets (no extra `count()` on `logs`). Alerts use the same rollups: count when the saved search has no `agg`, otherwise the window `stat` (invalid key or scan-budget refuse does not fire).
- Derived series live beside `q` as `agg=rate` or `agg=p99:duration_ms` (never inside the bar, never PromQL). Rate is count / bucket width from the volume histogram. p99/avg/min/max/sum of a numeric attr use `logs_attr_numeric_by_minute` when volume would use `logs_by_minute` and the bar is ≥1m; otherwise they scan matching `logs` rows with a hard read budget (`throw`, never a partial p99). Lookup/ignore keys refuse (`p99/avg need a numeric field`). Overflow / timeout of that scan returns `source: "refused"` (`p99/avg over this query exceeds the scan budget`). Window `stat` is the reducer over the window (p99 is not an average of per-bar p99s). Empty buckets are omitted (`null`), not a fake 0. Live 2s `since=` polls skip this logs-scan reducer; it refreshes on the 30s pass. Ingested metrics are a sibling source: `metric=cpu_seconds` with optional `ml=service:api` (equality matchers, cap 4). Overlay reducer is avg. Unlabeled reads `metrics_by_minute` when the bar is ≥1m; labeled matchers and sub-minute bars scan `metrics`. Log `q` does not filter a metric series. `metric=` and log `agg` are mutually exclusive on one widget. The histogram Series picker lists `GET /api/numeric-keys` (duration_ms first, cap 8, keep the URL key) plus Rate, then `GET /api/metric-names` (window, ignore log `q`, cap 8, keep the URL name). A quiet or logs-scan-shape window still offers duration_ms so the path stays visible. Saved searches store `agg` and optional widget layout (including `metric` / `metricLabels`) so Save round-trips the canvas. An alert watches that saved search’s **log** `agg` (count when off; window `stat` when on); metric-threshold alerts are not supported. Each widget chrome exports the painted series as CSV/JSON/SVG/PNG (download) and, on extra panels, Copy puts the same payload on the clipboard; the table footer still exports the loaded event page.
- Histogram chart: split by Level / Service / Host / None; stacked, grouped, line, or area; Linear / Log. Overlay or replace-Y for the derived series; a stat strip under the plot shows the window aggregate. Stacked draws one column at the scaled bucket total and slices it by share (log of a sum, never a sum of logs); 1px between columns, no gap inside a stack. Controls sit in one card header; the legend is under the plot. Interval chips (`Auto · 1m` or `1ms`…`7d`) pin bar width; a chosen width stands in (`15m*`) when the window cannot draw it. Wheel or `+`/`−` zooms about the cursor on a 1ms…365d ladder (1ms is the finest bar and the tightest window). Drag pans (span unchanged; axis ticks follow the preview so bars and times stay aligned); Shift+drag selects a span (floored at 1ms). Wheel, `+`/`−`, head-drill, Shift+drag, and mark peeks keep `to` at now the same way pan does (span unchanged); Absolute From/To can still type a future To. A 12px head strip above the plot is the commit: hover previews the drill, click drills to that ladder span around the bar, drag sweeps and pins. A plain click on the bars is a no-op. Search / Follow draw stored change marks on a 22px lane under the pinned plot (not extra widgets, Surroundings, or boards); wheel over the lane still zooms about the cursor. When the plot surface is focused, `←`/`→` pan one bucket; Shift+arrows pan one window. `+`/`−` zoom only with that focus. Wheel zoom does not need focus. Live pauses on pan/select. Axis ticks are HH:MM (HH:MM:SS under 15m or when the bar is <1m; HH:MM:SS.mmm when the bar is <1s or the window is ≤1s; `MM-DD` when the window is ≥1d, not today, or crosses midnight). Event-table / Surroundings / detail-head stamps follow that same date rule in compact Settings; Full is always `YYYY-MM-DD HH:MM:SS.mmm` (localStorage, not the URL). The strip above the card names `from → to` plus `UTC · span · bar width` (date on the stamp when the window is ≥1d or not today); Custom-window Reset there restores the window the exploration started from. The volume plot is a pinned cell at (0,0) on that grid (resize yes; move / × / Duplicate no). Search can host extra widgets (stat, top-N bars, more histograms) around it (cap 6 including the plot, ids `a`–`f`); Logs off hides the table and sends `events=0`. Top-N bars group by level/service/host or an attr key (`status`, `path`, …) from `GET /api/facets` / `GET /api/attr-facets` with `omit=0` (full `q`; sidebar facets still omit their own field) — counts of each value, not avg/max/min. A Top-N row opens Filter / Exclude (does not add a token on click). A `%` toggle on Top-N shows each row as a share of the window total (display-only; URL `.pct`). An **N** control (5 / 10 / 20, or Custom 1–50, default 10) caps named rows; `other` is the remainder only when N truncates the list; `.n20` is omitted when N is 10.
- Workspace tabs (uncapped, session-only, not in the URL) are investigations: New, Duplicate, Surroundings, Follow, and Saved / board opens. Overflow scrolls; past 5 tabs a muted count. Switching Search / Follow restores last paint when the hunt is unchanged. Copy-link is the active Search / Follow. **Surroundings** (detail footer; Fields/JSON stay the only detail tabs) opens a reader workspace so the search is not thrown away. Saved stays live on that reader. All is ±N on the same service (and host when set); Matching ANDs the inherited `q` via `q=` on `GET /api/search/context`. Earlier/Later raise N by 50 up to 200. A row click selects; footer Surroundings re-centers this tab. **Follow this value** opens a new Follow workspace (token-only `q`, custom ±5m) and leaves the prior search intact. **View trace** (same footer; hidden unless an alias is a 32-hex OTLP TraceId; `req-…` is Follow only) opens a waterfall tab on that workspace’s Results strip via `GET /api/traces/:id` — it does not write `q`. Cap 5 is that strip only (trace / profile). **View profiles** on a pinned span opens an icicle tab via `GET /api/profiles?trace_id=&span_id=` (32-hex trace, 16-hex span; exact `Link` only; empty when nothing is linked yet). Leave is the tab × or Results / Surroundings.
- Sidebar always facets level / service / host. Attr facets are opt-in (`af=`, Add facet, max 8). Clicks toggle a value in that field’s OR group; `only` / `clear` and the detail panel’s `+` write the same canonical `q`. `GET /api/facets` is core fields only (own filter omitted unless `omit=0`). `GET /api/attr-facets?attrs=` is pinned keys (same `omit`). `GET /api/attr-keys` lists keys in the current window. Add facet and Top-N attr pickers omit lookup/ignore. Prefix on a pinned group hits `GET /api/attr-values?key=&prefix=`. Level, service, and host (and attr-keys when the minute MV applies) use rollups; pinned attr values use the values rollup when the remaining query has no extra attr/message filters. Pinned attr values refresh on the 30s Live pass and on q / range / `af` change, not 2s.

Ingest flattens attrs with `flattenAttrs` into both the JSON `attrs` column and `attr_map`, so numbers are stored as strings in both. A derived key (alias, combine, bucket, local lookup) must already be a top-level stored attr — enrich is collector-owned; see the [ingest guide](ingest.md#enrich-at-the-collector). Direct ingest without a collector does not grow those keys. Ingest does write `e1` fingerprints; hunt with `e1:…` like any other attr. Change marks (`deploy` / `flag` / `incident` / `note`) are a separate table; they are not `q` terms. `GET /api/marks` lists them in a window (`before` / `after` neighbors). Search / Follow draw them on the pinned volume plot; selecting or hiding a mark does not rewrite `q`.
