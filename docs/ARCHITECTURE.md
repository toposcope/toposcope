# Architecture

Two containers. Logs, ingested metrics, spans, profile samples, and change marks live in ClickHouse. The control plane (saved searches, alert rules, tokens, settings) lives in SQLite in the app process. Logs never go in SQLite. Metrics, spans, profiles, and change marks are not written into `logs`.

This file is the **shipped** system.

```
[curl / OTLP / syslog / seed / browser]
         |
         v
   toposcope (Bun + Hono)
    |             |
    |             +-- SQLite  (control)
    |
    +-- ClickHouse HTTP  (logs + logs.trace_id bloom + message text index + logs_by_minute + logs_attr_keys_by_minute + logs_attr_values_by_minute + logs_attr_numeric_by_minute + metrics + metrics_by_minute + spans + profile_samples + change_marks)
```

Packaged `compose.yml` runs ClickHouse and one version-pinned Toposcope application. ClickHouse stays on the internal Docker network; the host exposes the application on `127.0.0.1:8080` and syslog UDP on `127.0.0.1:5514`. The packaged limits are 2 CPU / 4 GB for ClickHouse and 1 CPU / 512 MB for the application.

During local development, only ClickHouse runs in Docker. Vite runs at `127.0.0.1:5173` and proxies API requests to Hono at `127.0.0.1:8080`. See [CONTRIBUTING.md](../CONTRIBUTING.md) for local commands and load profiles.

The API `idleTimeout` is 120 seconds so long bounded searches are not killed by Bun's shorter default. Newest-first event pages widen their lookback before reading more of the window. HTTP ingest returns 503 when a write fails, or 429 with `Retry-After: 1` when ClickHouse is overloaded or insert capacity is exhausted. Syslog UDP cannot return 429, so it retries busy inserts in process.

## Contract

Every layer speaks `LogEvent` from `src/shared/log-event.ts`:

- `ts` — ISO-8601
- `service` — non-empty string
- `host` — optional
- `level` — `debug | info | warn | error | fatal`
- `message` — string
- `attrs` — optional JSON object. Ingest lifts `exception.type` / `exception.frames` when the sender already set them (dotted OTEL keys or a nested `exception` object), writes `e1` when frames are present (hash type + up to 50 `file`/`function`; if any frame is `in_app`, hash only those) or when `exception.type` is set or the level is `error`/`fatal` (type + a stabilized `message`), then flattens with `flattenAttrs` (`src/shared/attrs.ts`) into both a JSON string and `attr_map Map(LowCardinality(String), String)` so the JSON tab and filters cannot disagree. Values are strings (numbers become `"500"`). At most 50 keys per event (`e1` is stamped first so the cap cannot drop it). Flatten is **top-level only**: nested objects/arrays become JSON strings, not dotted paths. A dotted key (`http.status_code`) is one name if the sender already flattened it. Ingest does not parse stacks from `message`, does not rewrite old rows, and does not use log templates.

Ingest accepts one event, a JSON array (max 500), or NDJSON. Body cap is 1MB (decoded). OTLP gzip on logs, traces, and profiles inflates under that cap. Missing `ts` is stamped server-side.

**Ingest boundary:** Vector / Fluent Bit / Alloy parse lines, flatten nested JSON, and write any derived attr that `q` / Top-N / rollups must see (alias/copy, combine, bucket, local file lookup). Enrich is collector-owned; recipes live in the [ingest guide](ingest.md). Toposcope ingest stamps `ts`, caps keys, stringifies leftover objects, copies OTLP `traceId`/`spanId` onto attrs, fills `logs.trace_id` from `trace_id` / `traceid` / `request_id` / `req_id`, computes `e1` fingerprints, and writes ClickHouse. It does not eval user JS, call an HTTP API per event, own lookup files, or run a rule table. Direct `POST /api/ingest` / `POST /v1/logs` without a collector does not grow collector-style derived keys (alias/combine/bucket/lookup). A separate ingest daemon stays out.

OTLP `POST /v1/logs` accepts JSON (`application/json`) or protobuf (`application/x-protobuf`). Both map to `LogEvent`. Syslog UDP parses RFC 3164 into the same contract. OTLP `POST /v1/traces` maps `resourceSpans` to `Span` (`src/shared/span.ts`) and writes the `spans` table — not `logs`. OTLP `POST /v1/profiles` maps each decoded `Profile` to `ProfileSample` rows (`src/shared/profile.ts`) and writes `profile_samples` — not `logs` or `spans`. One `Profile` is one renderable unit; do not merge.

Query and facets read `attr_map`. `logs` has bloom skip indexes on `trace_id` and `mapValues(attr_map)`, and a text index on `lowerUTF8(message)` (`TYPE text`, `splitByNonAlpha`) so a message term can prune granules. `logs_by_minute` includes `host`. `logs_attr_keys_by_minute` rolls up attr **key names** per minute/service/level/host. `logs_attr_values_by_minute` rolls up indexable key/value pairs (≤64 chars; not JSON blobs or UUID-like ids) for single-attr histogram/count/facets. UUID-like / lookup-role / ignore-role equality scans `logs` (never the empty values summary) so histogram `total` matches the table. `logs_attr_numeric_by_minute` is the sibling for values that parse as finite numbers (count/sum/min/max and a p99 t-digest). Numbers stay strings in `attr_map`; the MV parses at insert. Ingested metrics live in `metrics` (name, value, labels map) with `metrics_by_minute` (count/sum/min/max, no labels). They are not written into `logs` and are not a PromTSDB. Unlabeled overlays read the metric MV; label matchers scan `metrics`. Overlay reducer is avg.

## Auth

- `GET /api/health` and `GET /api/metrics` are open.
- Browser UI and all other `/api/*` routes: HTTP basic auth, password `TOPOSCOPE_PASSWORD` (any username). Packaged boot refuses missing, empty, or demo (`toposcope` / `toposcope-ingest`) secrets and does not listen. `bun run dev` may fill localhost defaults.
- `POST /api/ingest` and `POST /v1/logs` / `POST /v1/metrics` / `POST /v1/marks` / `POST /v1/traces` / `POST /v1/profiles` also accept `Authorization: Bearer` — env `TOPOSCOPE_INGEST_TOKEN` or a hashed row from `api_tokens`.

## HTTP

- `GET /api/health` — `{ ok, clickhouse, sqlite }` (503 when not ok)
- `GET /api/metrics` — Prometheus text
- `POST /api/ingest` — JSON, JSON array, or NDJSON → `{ ingested }`
- `POST /v1/logs` — OTLP JSON or protobuf logs → `{ ingested }`. Optional `Content-Encoding: gzip` inflates under the 1MB cap.
- `POST /v1/metrics` — JSON metric point or array (max 500, 1MB) `{ name, value, ts?, labels? }` → `{ ingested }`. Same bearer/basic as log ingest. Not Prometheus scrape.
- `POST /v1/marks` — JSON change mark or array (max 500, 1MB) `{ kind, title, ts?, service?, attrs?, id?, end_ts? }` → `{ ingested }`. `kind` is `deploy` | `flag` | `incident` | `note`. Omit `id` and ingest mints `mk_…`. `end_ts` must be after `ts` (incident duration band on the hunt plot; other kinds stay points). Same bearer/basic. Writes `change_marks`, not `logs`.
- `GET /api/marks?from=&to=&range=&kind=&service=` — `{ marks, before, after }` (cap 500, oldest first). `before` / `after` are the nearest neighbors outside the window. `range` or `from`+`to` required. Basic auth. Search / Follow draw them on the pinned volume plot; extra widgets, Surroundings, and boards do not.
- `POST /v1/traces` — OTLP JSON or protobuf traces → `{ ingested }`. Same bearer/basic, 1MB decoded body (gzip under that cap), and 500-span batch as log ingest. 429 when ClickHouse is busy. Maps `resourceSpans` onto `spans` (not `logs`). Store what arrives; sampling stays at the collector.
- `GET /api/traces/:trace_id` — `{ spans, total }` for one request. The id must be 32 hex, not all zeros (400 otherwise; lowercased). 200 even when empty — not a 404. Cap 500 keeps the longest-duration branches plus their ancestors; `total` is the unclipped count. View trace joins when a log alias (`trace_id`, then `request_id`, then `traceid` / `req_id`) is that 32-hex shape; `req-…` is Follow only. Histogram / Follow / `q` stay on `logs`.
- `POST /v1/profiles` — OTLP JSON or protobuf profiles → `{ ingested }`. Same bearer/basic, 1MB decoded body (gzip under that cap), and 500-`Profile` batch as log ingest. 429 when ClickHouse is busy. One decoded `Profile` is one renderable unit; do not merge. Store unlinked samples with empty `trace_id` / `span_id`. Sampling and whether `Link`s are attached stay at the collector.
- `GET /api/profiles?trace_id=&span_id=` — one Profile’s samples linked to that pair (200 even when empty). Requires a 32-hex `trace_id` and a 16-hex `span_id` (400 otherwise). If several Profiles match, pick the latest (`total_profiles` is the matching count, including the one rendered). Fold identical stacks inside that Profile only. Cap 500 heaviest stacks; `total_samples` is the unclipped folded stack count.
- `GET /api/search?from=&to=&range=&q=&cursor=&since=&limit=&split=&step=&agg=&metric=&ml=&events=` — `{ events, histogram, total, nextCursor, from, to, ingested?, agg?, scan? }`. `split` is `level` (default), `service`, `host`, or `none`. `step` is `1ms|10ms|100ms|1s|10s|1m|5m|15m|1h|4h|1d|7d` (omit for auto). `agg` is `rate` or `{avg|min|max|sum|p99}:key` (omit for volume only). `metric` is an ingested metric name (`cpu_seconds`); `ml` is optional label matchers (`service:api,host:api-1`, cap 4). `metric=` skips log `agg` and does **not** apply log `q`. `events=0` skips the event page and lookback widening (histogram/`agg`/`total` still run). `since` (ISO) is the live-tail delta: events with `ts >= since`, histogram only from that bucket onward. `cursor` (ISO, Load more) is events-only: `histogram` is `[]` and `total` is `0` (the UI keeps the first search’s chart). `total` is otherwise the sum of the returned histogram (partial when `since` is set; the UI merges). `ingested` is whether `logs` has any row (not this window). Full searches that already have histogram/event hits set it true without a probe; an empty window probes `SELECT 1 … LIMIT 1`. Load-more and empty live `since=` deltas omit it so the UI keeps the last known store state. `agg` is `{ expr, source: numeric|rate|refused|metric, reason?, buckets: [{ t, v }], stat }`. Rate is count / bucket width from the volume histogram. Numeric reducers use `logs_attr_numeric_by_minute` only when volume would use `logs_by_minute` and the bar is ≥1m; message terms, extra attrs, a single-attr `q`, or a sub-minute bar scan `logs` with the read budget rather than lie from a minute rollup. Metric overlays use `metrics_by_minute` when unlabeled and the bar is ≥1m (avg), or scan `metrics` when `ml=` is set or the bar is sub-minute. Window `stat` for p99 is `quantileTDigestMerge` over the window, not an average of per-bucket p99s. Load-more skips `agg`.
- `GET /api/search/context?ts=&service=&host=&n=&q=` — `{ before, after }` surrounding events (default 50, max 200) on the same service, and host when `host` is set. Optional `q` ANDs the search bar (Matching).
- `GET /api/search/around?ts=&from=&to=&q=&n=` — `{ before, after }` (default 50, max 200) in the hunt window, not scoped to a service. Focus in logs opens Surroundings titled with the mark (50 older above, 50 newer below). It does not rewrite `q`. Optional `q` ANDs a filter. `before` is older (oldest first); `after` is newer (closest first).
- `GET /api/facets?from=&to=&range=&q=&limit=&omit=` — `{ level, service, host }`, each a top-N `{ v, n }` list (default 10, max 50). Each field omits its own filter so the sidebar can switch values; `omit=0` keeps the full `q` (Top-N).
- `GET /api/attr-keys?from=&to=&range=&q=` — `{ keys: [{ k, n }] }` (up to 200) for Add facet
- `GET /api/attr-facets?from=&to=&range=&q=&attrs=path,user_id&limit=&omit=` — `{ [key]: [{ v, n }] }` top-N per pinned key (max 8 keys; default 10 values, max 50). Same `omit` as `/api/facets`.
- `GET /api/attr-values?from=&to=&range=&q=&key=&prefix=` — `{ values: [{ v, n }] }` prefix match on one map key
- `GET /api/numeric-keys?from=&to=&range=&q=` — `{ keys: [{ k, n }] }` numeric-rollup keys when the minute MV applies (empty otherwise). The histogram Series picker uses this list (duration_ms first, cap 8, keep the current `agg` key) with p99/avg/max/min/sum; Rate is always on the menu.
- `GET /api/metric-names?from=&to=&range=` — `{ keys: [{ k, n }] }` ingested metric names in the window from `metrics_by_minute`. Ignores log `q`. The Series picker lists these beside log keys (cap 8, keep the URL name).
- `GET /api/throughput` — `{ per_second, histogram: [{ t, n }] }`. Live events/s (last 5s of ingest, else last minute / 60). Histogram is 60 minutes from `logs_by_minute`. No extra store; the status footer draws it as an inline sparkline next to `/s`. Click opens search `range=1h` with Live on.
- `GET /api/system` — `{ app, clickhouse }` process stats: `mem_used`, `mem_limit` (cgroup, or null on the host), `disk_used` / `disk_total` (ClickHouse default disk; app `disk_used` is the SQLite file), `cpu` (percent of cgroup CPUs, or of one core), `io_read` / `io_write` (bytes/s, ClickHouse only). First poll has null rates. ClickHouse comes from `system.metrics` / `system.asynchronous_metrics` / `system.events`; the app from RSS + cgroup files. No Docker socket. `clickhouse` is null if the query fails.
- `GET/POST /api/saved-searches`
- `PUT /api/saved-searches/:id` — name, query, range / from_ts / to_ts, optional `agg`, `widgets` (grid JSON), and `cols` (promoted hunt-table keys, cap 3); copies `query` onto linked alert rules
- `DELETE /api/saved-searches/:id` — 409 if an alert rule references it
- `GET /api/saved-searches/:id/run` — search result plus `count`, `value` (the saved search’s series: count or window `stat`), `refused`, `reason`
- `POST /api/saved-searches/:id/test` — `{ count, value, agg, refused, reason, sample }`
- `GET/POST /api/alert-rules` — `PUT /api/alert-rules/:id` — `DELETE /api/alert-rules/:id`. `threshold` is a positive finite number.
- `GET/POST /api/api-tokens` — `DELETE /api/api-tokens/:id` (create returns `token` once)
- `GET/PUT /api/settings` — `{ retention_days }`
- `GET/PUT /api/fields` — `{ roles, links }` in SQLite. `roles` is attr key → `chart` | `lookup` | `ignore` (omit unset; default chart). `links` is log attr key or `service`/`host` → metric label (cap 8). Not in the search URL. Roles apply to new ingest only. `GET ?wave=keys|values|suggest` returns that catalog slice (`cheap=` for suggest tops); omit `wave` for the full catalog. `PUT` writes SQLite and returns `{ roles, links }` only.

`q` is compiled by `src/query/compile.ts` (boolean AST → parameterized SQL). A parse error is 400 `{ error, faults }`. See [query.md](query.md). `range` (`15m`, `1h`, `4h`, `24h`, `7d`, or `\d+(ms|s|m|h|d|w)` up to 365d) is resolved with `Date.now()` in the search handler and overrides `from`/`to`. Custom `from`/`to` spans clamp to 365d. Histogram buckets are `{ t, n, series, by_level }`. Bar width is auto (finest of `1ms`…`7d` with ≤200 bars: 15m → `10s`, 1h → `1m`, 30d → `4h`, 365d → `7d`) unless `step=` pins a tick (clamped: 1–500 bars; 1 legal at the 1ms floor). Interval `< 1m` scans `logs`. `split=level|service|host|none` (default level) chooses the series keys. Level/service/host/none read `logs_by_minute` when the bar is ≥1m and `q` has no message terms and no attr filters. A single attr equality reads `logs_attr_values_by_minute` unless the value is UUID-like or the key is lookup/ignore (then `logs` + bloom). A comparison (`duration_ms:>100`) scans `logs`. A message term reads `logs` (text index on `message`, not `logs_by_minute`). A `logs` volume histogram always uses the read budget (including `1m+` bars); overflow returns `scan: { source: "refused", reason, histogram, events }` (200), not a 500. Service/host series cap at 8 keys plus `other`. `total` is the sum of histogram buckets. Optional `agg` adds a derived series (`rate`, or avg/min/max/sum/p99 of a numeric attr) from the volume histogram, `logs_attr_numeric_by_minute` when volume would use `logs_by_minute`, or matching `logs` rows (budgeted) when volume already scans `logs`. Overflow of that agg scan refuses the reducer (`source: "refused"`) instead of a partial p99. Optional `metric=` overlays an ingested metric (avg) from `metrics_by_minute` / `metrics`; log `q` is not applied to that series. Mutually exclusive with `agg` on one request. Events paginate with `cursor` = oldest `ts` on the page. A newest-first page widens lookback from `to`/`cursor` (1m → 365d, clamped to `from`) instead of sorting the whole window. The floor / last lookback is budgeted the same way as a logs histogram. Load-more (`cursor=` without `since=`) skips the histogram and `agg`. `since=` live deltas skip lookback widening and already have a tight bound. Live polls send `since` (newest event, or last `to`) so ClickHouse only reads new rows and the in-progress histogram bucket; the UI merges those into the open page and fills the sliding window. A full search (no `since`) still runs every 30s while Live is on. Mergeable extra timeseries refresh on the 2s `since=` poll; whole-window aggregates stay on the 30s pass. Live chrome shows last-updated age only on cards that missed the last 2s poll.

Facets drill down: each field is counted with its own filter removed, so `level:error` still lists every level while `service` and `host` narrow. A field may hold several values OR’d as `(level:error OR level:fatal)`; counts still omit that field’s own filter. Top-N widgets call the same endpoints with `omit=0` so they follow the full `q` (a Level Top-N with `level:error` shows error, not every level). Level, service, and host use the matching rollup (`logs_by_minute` or `logs_attr_values_by_minute`). Attr facets are opt-in (`af=` in the URL, max 8). Key names come from `logs_attr_keys_by_minute` when the minute MV applies, otherwise `mapKeys` on matching `logs`. Add facet and Top-N attr pickers omit lookup/ignore keys (Follow is the lookup path; the search-bar field menu still lists them). Pinned value lists and prefix search use the values rollup when the remaining query has no message/attr filters; otherwise they scan `attr_map` on `logs`. Pinned attr values refresh on the 30s Live pass and on q / range / `af` change, not 2s.

Fields (`?view=fields`) is a header view in the Alerts shell. The table lists the shared Search window’s keys (core `service` / `host` / `level` / display-only `message`, then Add facet’s chart keys plus lookup/ignore as “not charted”): event count, distinct values when the key is charted else “not charted” (`message` Values is `—`, Role `text` — not a picker). Role is `chart` default / `lookup` / `ignore` on attrs; optional metric-label link (cap 8). The catalog paints in three waves (keys, values, suggestions) with Stop / elapsed / a 2px bar; a window change dims the previous rows. Suggestions (role tint, dashed link chip) never write a row until clicked. Graph on a linked event-detail field sets `metric=` + `ml=` from the link; `+` still adds `key:value` to `q`. **Follow this value** (lookup or id-shaped Fields row) opens a new Follow workspace: token-only `q`, custom ±5m, Live off; the previous workspace stays. Widening or shrinking that window while still following is not supported. Roles are per key name (nginx `type` and sendmail `type` are one field).

The operator UI (Vite + React + shadcn/Tailwind, no React Router) keeps search state in the page URL via `history.replaceState`. Copy-link and back/forward restore the same search. The hunt table can show up to three extra attr columns between Host and Message (`cols=`); values come from the loaded page; missing cells are an em dash; Message-header `+` adds, header `×` removes. Follow copies the parent tab’s columns; New starts empty; Surroundings stays five-col. Saved searches store the same list. Sidebar field counts (saved searches, facets) default to compact `1.24K` / `3.04M`; Settings toggles Count format (human vs raw) and Timestamps (compact vs full) — this browser, not `/api/settings`. Compact event stamps follow the histogram date rule (`HH:MM:SS`, or `MM-DD HH:MM:SS` when the window is ≥1d, not today, or crosses midnight); Full is always `YYYY-MM-DD HH:MM:SS.mmm`. Hover `title` is the stored ISO. Params:

- `q` — search bar
- `range` — `15m` | `1h` | `4h` | `24h` | `7d` | any `\d+(ms|s|m|h|d|w)` ≤ 365d (e.g. `90m`, `30d`, `2w`), or `custom` with `from`/`to` (ISO)
- `live=1` — live tail
- `saved` — saved-search id
- `split` — histogram series: `level` (default) | `service` | `host` | `none`
- `chart` — `stacked` (default) | `grouped` | `line` | `area`
- `scale=log` — log Y axis (omit for linear)
- `step` — histogram bar width `1ms` | `10ms` | `100ms` | `1s` | `10s` | `1m` | `5m` | `15m` | `1h` | `4h` | `1d` (omit for auto)
- `agg` — `rate` or `{avg|min|max|sum|p99}:key` overlay on the histogram (omit when off or when `metric=` is set)
- `metric` — ingested metric name (`cpu_seconds`) overlay (omit when off)
- `ml` — metric label matchers `service:api,host:api-1` (omit when none; cap 4)
- `y=agg` — replace the volume Y axis with the derived series (omit for overlay)
- `logs=0` — hide the event table (omit for logs on)
- `w` — compact 12-col widget grid (omit for today’s single histogram)
- `af` — comma-separated pinned attr facet keys (`path,user_id`); omit when none
- `cols` — comma-separated promoted hunt-table keys (`path,status`); omit when none; cap 3; Search and Follow
- `view=alerts` — alerts watchlist (omit for search)
- `view=fields` — fields catalog (omit for search). Roles/links are not URL state; `range=` / `from` / `to` stay so the clock matches Search.

Examples: `/?q=level:error&range=1h&live=1` and `/?view=alerts`. Save in the search bar updates the active saved search (Save as… makes another). Alerts are a separate view; each rule watches a saved search.

Esc returns to Results.

## Retention

TTL is `toDate(ts) + INTERVAL {n} DAY` on `logs`, `metrics`, `spans`, `profile_samples`, and `change_marks`, and `toDate(minute) + INTERVAL {n} DAY` on `logs_by_minute`, `logs_attr_keys_by_minute`, `logs_attr_values_by_minute`, `logs_attr_numeric_by_minute`, and `metrics_by_minute`. `n` comes from SQLite settings (default 30, clamp 1–365). Boot and `PUT /api/settings` apply `ALTER TABLE ... MODIFY TTL` with `mutations_sync = 0, alter_sync = 0` (issue the change; do not wait for `MATERIALIZE TTL`). Tables already at `n` are left alone. `PUT` writes SQLite first so a later ClickHouse error cannot roll back the setting. Unfinished TTL mutations are killed before the new `ALTER` so a failed materialize does not block the next save.

## Alerts

Each rule points at a saved search, a positive finite threshold, and an `http(s)` webhook. An in-process loop (60s) evaluates that search’s `agg` over its window the same way Search does: `countLogs` when `agg` is null; window `stat` for `rate` or `{avg|min|max|sum|p99}:key`. A refused agg (invalid numeric key or scan budget) does not fire. ClickHouse down or unexpected SQL writes `last_status=error` without a POST. If `silenced_until` is in the future, it skips. If `value >= threshold` and the cooldown (saved `range`, else 5m) has elapsed, it POSTs. Slack incoming webhook URLs (`hooks.slack.com`) get a Slack message that names the series (`p99(duration_ms) 912 ≥ 800`); other URLs get `{ alert, count, value, agg, query, fired_at }`. `count` is still the matching volume so existing generic hooks do not go silent. `last_attempt_at` is last cron processing that was a refuse, an eval error, or a POST. `last_status` is `200` | HTTP code | `timeout` | `error` | `refused`. A 2xx sets `last_fired_at` and clears `consecutive_failures`; webhook failures increment `consecutive_failures` and do not start cooldown. Refuse and eval error do not increment `consecutive_failures` and do not touch `last_fired_at`. A successful eval that does not POST clears `last_status` / `last_error` when they were `refused` or `error`. Changing the webhook URL clears the attempt fields. PUT `silence_for` (`1h`|`4h`|`24h`) or `silenced_until` (ms epoch, or `null` to clear). Widget layout does not change `shouldFire`.

## Tenancy

`tenant_id` is a column and is always `'default'`.

## Backup and recovery

Packaged data spans two Docker volumes: ClickHouse `ch_data` and application `app_data`. A complete backup must include both. Application rollback and ClickHouse data recovery are separate operations; an image pin cannot repair an incompatible data directory.

See the [operations guide](operations.md#backup-and-restore) for backup, restore, and rollback commands.
