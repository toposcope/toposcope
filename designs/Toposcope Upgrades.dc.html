19c

A patch is out: 0.6.0 → 0.6.1, and the panel that says what to do

The footer item gains an arrow and the new version in plate, and stays the same size and grey. Clicking it opens the panel: Before you upgrade first, then what's new, then the one command to run on the host.

  1. The footer. 0.6.0 → 0.6.1, nothing louder: no badge, no red, no banner. It is noticed by someone who looks at the footer every day.
  2. Before you upgrade, first and apart. Behaviour operators rely on that changes, new settings, whether a backup matters. Someone who reads one part reads this one. It comes from the release's own **Before you upgrade:** paragraph.
  3. What's new. The release notes as published, plain paragraphs, inline code and links only.
  4. The command, the only action. Copy puts exactly ./toposcope.sh upgrade 0.6.1 on the clipboard (19f). The app never runs it: it would need the Docker socket.
  5. The backup. Its size comes from what the ClickHouse and App meters already read, so nobody is surprised by minutes of downtime.
  6. The quiet line. When the check last ran; a failed or switched-off check is said here (19g), never in the footer.

Before you upgrade

From this version Toposcope asks GitHub once a day whether a newer release is out. It sends nothing about this instance. Set TOPOSCOPE_UPDATE_CHECK=off in .env to stop it.

What's new in 0.6.1

Toposcope knows when a release is out. Once a day it reads GitHub's public list of releases and keeps what is newer than the one running. GET /api/version says what it found.

The footer shows the running version, and the newer one when there is one, with this panel.

toposcope.sh upgrade backs up both stores, swaps compose.yml, waits for the new version, and rolls back by itself if it does not come up.

Every release ships SHA256SUMS, and toposcope.sh is a release file.

Upgrade

Run it on the host, in the directory that holds compose.yml.

./toposcope.sh upgrade 0.6.1

Backs up both stores first: about 1.2 GB (ClickHouse 1.16 GB, SQLite 41 MB). Ingest stops while it runs. Add --no-backup to skip it.
